# Квантование и прунинг · выводы для презентации

PTQ преобразует готовые веса без градиентного дообучения. В экспериментах Ирины есть прунинг из готового чекпойнта без дообучения и итеративный прунинг с восстановлением качества. Первый даёт сравнение методов при одинаковом бюджете дообучения в ноль эпох. Второй показывает качество всего пайплайна с дополнительным обучением.

## CV · LeNet + BatchNorm, MNIST

| Метод | Top-1 | Δ к FP32 | Файл весов | Дообучение |
|---|---:|---:|---:|---:|
| FP32 | 98,55% | 0 п. п. | 179,23 КиБ | 0 эпох |
| INT8 PTQ per-channel MinMax | 98,52% | −0,03 п. п. | 56,42 КиБ | 0 эпох |
| LAMP, пять шагов, ratio 0,60 | 76,17% | −22,38 п. п. | 55,98 КиБ | 0 эпох |
| LAMP, пять шагов, ratio 0,60 + fine-tuning | 99,04% | +0,49 п. п. | 55,98 КиБ | 10 эпох |
| Плотный контроль + fine-tuning | 99,28% | +0,73 п. п. | 179,23 КиБ | 10 эпох |

**Фраза для слайда.** «При размере около 56 КиБ INT8 PTQ сохранил 98,52% accuracy, а LAMP без дообучения получил 76,17%. С десятью дополнительными эпохами LAMP достиг 99,04%. Плотная модель с тем же бюджетом обучения достигла 99,28%.»

Это прямое сравнение на одном чекпойнте, тесте и формуле измерения файла. Дообучение подняло результат LAMP на 22,87 п. п. при одинаковом размере файла. PTQ преобразует выходной слой, а LAMP защищает его при удалении каналов. LAMP переоценивает важность каналов на каждом шаге, поэтому fine-tuning может менять набор удалённых каналов. Измерение покрывает один seed и один чекпойнт.

Для задержки условия общие. На AMD Ryzen 5 5600 при одном потоке и batch 256 INT8 per-channel MinMax занял около 4,21 мс против 8,64 мс у FP32 и 8,59 мс у дообученного LAMP. При batch 1 получено около 0,59, 0,28 и 0,29 мс соответственно. В исторических сериях исходные веса различались, размер прунинга вычислялся по числу параметров, а время измерялось в другой среде.

## Трансформеры · SmolLM-135M, WikiText-2

**Фраза для слайда.** «На одном SmolLM-135M и WikiText-2 test 8-битный RTN в MLP дал PPL 18,40 при оценочной экономии 28,9%. Глобальный Magnitude в MLP без дообучения дал PPL 745 667,23 при оценочной экономии 29,6%. Исходная PPL модели — 18,39».

Общий прогон выравнивает чекпойнт, токенизатор, тест, окно 512, шаг 256, охват MLP и нулевой бюджет дообучения. Экономия — оценка полезной нагрузки относительно FP16. Для RTN учитываются коды, scale, zero point и веса слоёв в FP16. PPL для RTN считалась на восстановленных плотных весах. Для вывода о размере использована расчётная нагрузка, для CV выше — фактические файлы. Доля прунинга задаёт целевое удаление внутри MLP, а экономия относится ко всей модели.

Исторические W4/GPTQ/AWQ и LAMP/Taylor + LoRA дают контекст. Основная серия квантования использовала SmolLM2, Pythia и OPT на validation с окном 1024, а Ирина использовала SmolLM на test с окном 512. В старых LoRA-сериях также изменялись критерии важности и бюджет обучения. Сопоставимость здесь оценивается по протоколам. Статистическая эквивалентность потребовала бы заранее заданного допуска и независимых повторов.
