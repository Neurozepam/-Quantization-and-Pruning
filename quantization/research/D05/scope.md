# D05 — scope v0: activation clipping

## Решение

Продолжить D04: PTQ, статическое симметричное fake-квантование активаций. Weight-only не является задачей этого эксперимента. Выбор согласован с пользователем в сессии D05.

Направление явно зафиксировано как PTQ: используем уже обученную модель, не обучаем её веса; исследуем выбор параметров квантования по calibration. QAT и обучение модели с учётом квантования вне scope текущего sprint. Это ограничивает вычислительную стоимость и число изменяемых компонентов, но не гарантирует простой поиск научной новизны.

Сегодня: аудит и измерение стоимости. Реализация собственного метода ещё не выбрана; новизна и эффективность не установлены.

## Исходная конфигурация

- Model: HuggingFaceTB/SmolLM2-135M.
- Revision: 93efa2f097d58c2a74874c7e644dbc9b0cee75a2; проверена в metadata снимка D04. Новые загрузки явно фиксируют revision.
- FP32, eval(), inference_mode(), eager attention, use_cache=False.
- Исходный локальный слой: model.layers.0.mlp.down_proj, W[out,in] = [576,1536].
- Квантуется X; W остаётся исходной. Y = X W^T, Y_hat = X_hat W^T.
- INT4, коды -7..7, один симметричный scale на весь вход слоя, s = alpha/7.
- Порог определяется на calibration и фиксируется при оценке.
- Диагностическая метрика: mean((Y - Y_hat)^2); activation MSE и clipping fraction — вспомогательные.

## Проверяемая проблема, а не готовый вывод

Проверить, меняются ли выбранные по calibration output MSE пороги при смене calibration subsets, и приводит ли это к воспроизводимому ухудшению переноса на development.

Потенциальное направление: устойчивый выбор порога по нескольким subsets. Формула пока не зафиксирована. До реализации необходимы failure-mode experiment и поиск ближайших работ.

D04 не доказал calibration overfitting: среди трёх проверенных правил смены лучшего при переносе не обнаружено. Победа p99.9 относится только к локальному опыту на искусственных текстах.

## Данные и независимость

- Снимок D04 используется для отладки и timing, а не как единственное основание исследования.
- Evaluation D04 уже участвовала в выборе направления; считать её exploratory/development, не финальным test.
- Выбран Salesforce/wikitext, config wikitext-2-raw-v1, revision b08601e04326c79dfdd32d625aee71d232d685c3. Train для calibration, validation для development; test не загружен нашими скриптами и не оценивался.
- D05 smoke manifest: data/wikitext_blocks.json; 8 calibration subsets по 2 фрагмента × 128 токенов, development 16 × 128 токенов. Пулы: первые 64 подходящие train-статьи и все 60 validation-статей. Это ограниченный пилот, не полный основной протокол. Calibration subsets могут пересекаться.
- Calibration выбирает параметры фиксированной процедуры; development выбирает варианты процедуры; test оценивает замороженную процедуру.
- Настройка после просмотра test лишает его роли независимой финальной проверки изменённого метода.

## Контроли и baselines

Для будущего сравнения: FP, max-abs, фиксированный percentile, выбор alpha по calibration activation MSE, выбор alpha по calibration output MSE, ближайший найденный метод, proposed при наличии.

При проверке нового objective фиксировать слой, разрядность, granularity, общий calibration token budget и candidate thresholds. Учитывать стоимость поиска отдельно. Не давать subsets больше суммарных токенов без соответствующего контроля.

## Timing smoke

- FP forward на CUDA: batch=1, длины 32 и 128, прогрев и три повторения; загрузка и токенизация вне времени forward.
- Локальный поиск на CPU: representative из снимка D04, 256 токенов; 21 alpha от 0.1 до 10 с логарифмическим шагом; objective output MSE. Сетка предназначена для timing, не объявляется окончательной исследовательской сеткой.
- CPU thread count и конфигурация фиксируются в отчёте.
- CUDA синхронизируется до и после измеряемого участка.
- Все повторы и сбои сохраняются; старые артефакты D04 не перезаписываются.

## Границы claims

Локальная output MSE не заменяет perplexity полного forward. Fake quantization не доказывает runtime speedup, экономию VRAM или наличие низкобитного checkpoint. Одна маленькая модель не позволяет делать выводы обо всех LLM.
