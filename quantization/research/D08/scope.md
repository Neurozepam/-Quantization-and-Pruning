# D08 — Задача

Основной режим — W-only PTQ, 4-битные веса, группы по 128. Рабочая модель SmolLM2-135M; дополнительные Pythia-160M и OPT-125M.

## Покрытие

Квантуются все обычные Linear внутри Transformer-блоков. Embeddings, нормализации, LM head и bias остаются FP; активации не квантуются.

Quantizer — uniform affine asymmetric, коды 0–15, min–max с включением нуля. Группы идут по входным столбцам отдельно для каждой output row. Последняя неполная группа без padding.

Качество проверяется с восстановленными FP32-весами после quantize/dequantize. Это не packed checkpoint и не опыт на ускорение.

## Сравнение

FP → RTN → GPTQ. Для GPTQ настройки зафиксированы в [baseline_plan.md](baseline_plan.md). PPL считается по суммарному next-token NLL и числу targets.

Calibration выбирает параметры, development используется для оценки вариантов, test остаётся закрытым. Сетки по development не расширялись. QAT пока только в небольшом CPU-примере, не в основной матрице.

D06–D07 были activation-only; их выводы автоматически на веса не переношу. D07 NO-GO и его критерии не менялись.

## Статус

Полный forward RTN/GPTQ на трёх моделях работает: [ppl_results.md](ppl_results.md). Собственного quantizer пока нет. Следующий шаг — расширить проверку известных методов и определить сопоставимый сильный baseline.

Для новой идеи нужно показать изменение отображения, уровней или выбора кодов, проверить аналоги и отделить эффект от дополнительного calibration/compute/storage. Другая функция выбора прежнего clipping сама по себе цель не закрывает.
