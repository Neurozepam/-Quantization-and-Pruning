# D06 — Проверка переноса

Дата: 12.10.2026. Второй день research sprint после D01–D04 и D05.

## Задача

Проверить выбор статического INT4 clipping threshold по calibration и его перенос на development. Квантуются активации входов `model.layers.{0,15,29}.mlp.down_proj`; исходные веса FP32 не изменяются. Собственный метод пока не выбран.

Протокол: [protocol.md](protocol.md). Ближайшие работы: [related_work.md](related_work.md).

## Полный forward

Calibration: 256 входных токенов subset 0. Development: 16 отдельных блоков по 128 токенов, 2032 оцениваемых targets. Пороги определены только по calibration. Замена выполняется на текущих входах слоя, поэтому ошибки предыдущих участков распространяются дальше.

| Вариант | Mean token NLL | Perplexity |
|---|---:|---:|
| FP | 3.679307 | 39.618946 |
| max-abs, слой 0 | 4.383104 | 80.086246 |
| max-abs, слои 0/15/29 | 5.569121 | 262.203574 |
| p99.9, слой 0 | 3.895801 | 49.195439 |
| p99.9, слои 0/15/29 | 4.007523 | 55.010438 |
| FP после снятия hooks | 3.679307 | 39.618946 |

p99.9 в этом диагностическом запуске даёт меньшую деградацию, чем max-abs. Это perplexity ограниченных блоков, а не стандартный full-corpus benchmark или оценка правильности ответов.

FP после снятия hooks точно совпал с исходным агрегированным NLL. SHA256 полного состояния модели до и после одинаков.

## Локальные контроли

Правила: max-abs, p99.9, минимум calibration activation MSE, минимум calibration output MSE. В каждом запуске 256 calibration-токенов и 2048 development-токенов; используются сохранённые FP-входы и исходные веса слоя.

Первый контроль показал небольшой проигрыш output-MSE selection на слое 0 (+0.49% development output MSE относительно p99.9) и улучшения на слоях 15/29. Затем без изменения протокола выполнены все восемь subsets.

В таблице ниже знак «−» означает меньшую development output MSE, чем у p99.9. Проценты усреднены по парным сравнениям subsets, не по абсолютным ошибкам разных слоёв.

| Слой | Исходная сетка: средний delta | Плотная сетка: средний delta | Плотная: проигрыш / выигрыш / ничья |
|---|---:|---:|---|
| 0 | +0.4181% | +0.2873% | 3 / 4 / 1 |
| 15 | −17.8871% | −18.1076% | 0 / 8 / 0 |
| 29 | −6.0469% | −6.3903% | 0 / 8 / 0 |

Выбор порога меняется между subsets, но это не приводит к систематическому ухудшению на всех слоях. На слоях 15/29 обычный output-MSE search выигрывает у p99.9 во всех восьми сравнениях. На слое 0 сигнал слабый и неоднородный: для плотной сетки медианный delta −0.1254%, диапазон от −0.3583% до +2.8394%.

## Проверка плотности сетки

К 101 исходной точке добавлены 100 геометрических середин соседних интервалов. Точные исходные float32-значения и дополнительные p99.9/max-abs candidates сохранены. Выполнено одно заранее описанное уплотнение после просмотра исходных development-результатов.

Проверено:
- все 2472 исходные строки candidate losses присутствуют среди 4872 новых;
- calibration-метрики старых candidates воспроизводятся с допуском `rtol=atol=1e-6`;
- fixed-rule результаты не изменились;
- минимумы обоих calibration objectives не выросли;
- веса, входные tensors и файл снимка не изменились; test не использовался.

На слое 0 output-MSE winner изменился в 3 из 8 subsets. Средний calibration objective снизился на 0.1130%; среднее парное изменение development MSE относительно исходного search — −0.1303%.

Разброс порогов и разброс ошибок не эквивалентны: на слое 0 sample std выбранного alpha уменьшился с 0.23375 до 0.22182, а sample std development normalized MSE вырос с 0.00094841 до 0.00099800.

Суммарное время shared calibration search по 24 задачам: 7.8961 с против 16.5890 с (~2.10×). Вычисление rule thresholds и development evaluation сюда не входят. Это не время inference.

## Вывод и ограничения

- Сильный общий failure mode calibration overfitting в проверенном режиме не установлен. Плотность сетки частично влияет на слабое поведение слоя 0, но не полностью устраняет средний проигрыш.
- Subsets могут пересекаться; восемь результатов не являются независимыми статистическими повторами. Development ограничен одним корпусом и уже использован в exploratory-анализе.
- Выделение слоя 0 после просмотра результатов допустимо только как exploratory-направление. Результаты остальных слоёв сохраняются.
- Fake quantization не доказывает экономию памяти, ускорение или наличие низкобитного checkpoint.
- Проверена только SmolLM2-135M. Ни устойчивость на других моделях, ни научная новизна, ни эффективность proposed-метода пока не установлены.

## Следующий этап

Не продолжать адаптивно уплотнять сетку. Завершить проверку близких механизмов и выбрать один ограниченный pilot с одинаковыми данными/candidates и сопоставимой стоимостью поиска либо один обоснованный резервный вариант. Если устойчивого сигнала нет, сохранить отрицательный результат вместо добавления нового компонента ради таблицы.
