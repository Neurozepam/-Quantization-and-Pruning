# DAY 4 — Карта квантования SmolLM2-135M

## Путь данных

```text
token IDs → embedding
→ 30 Transformer-блоков:
    RMSNorm → Q/K/V → RoPE на Q/K → causal attention → O → residual
    RMSNorm → gate/up → SiLU(gate) ⊙ up → down → residual
→ финальный RMSNorm → LM head → logits
```

Веса Linear имеют соглашение W[out, in]. Embedding и LM head используют общую матрицу весов. Модель использует grouped-query attention: 9 query-голов, 3 key/value-головы.

## Тензор → место → возможность квантования → риск

Возможность ниже означает предмет исследования, а не наличие быстрого INT-kernel на GTX 1050 Ti. В текущей реализации все вычисления модели выполняются в FP32.

| Тензор | Где возникает | Что можно исследовать | Механизм риска |
|---|---|---|---|
| Веса embedding и выбранные embedding-векторы | Lookup по ID токенов | Квантование таблицы весов и/или её выходных векторов | Ошибка входного представления передаётся следующим блокам; общие веса с LM head связывают два места использования |
| Активации и gamma RMSNorm | Перед attention/MLP, после последнего блока | Квантование возможно исследовать; в нашем опыте операция и gamma остаются FP32 | Ошибка входа влияет на числители и общий знаменатель нормировки; нормировка не гарантирует отсутствия выбросов |
| Q/K | q_proj/k_proj, затем позиционное преобразование RoPE | Квантование весов проекций и/или активаций | Ошибка скалярных произведений может изменить веса внимания |
| V | v_proj | Квантование весов проекции и/или активаций | При фиксированном A ошибка результата равна A(V−V_hat) |
| A — веса внимания | Softmax от scores с маской | Квантование выходов softmax; в текущем опыте оставляем FP32 | Ошибки меняют доли смешивания; без перенормировки округлённые веса могут перестать суммироваться в 1 |
| Вход/выход O-проекции | После объединения результатов голов | Квантование весов и/или активаций | Ошибка смешанного контекста попадает в residual-добавку |
| Residual state | Сложение исходного hidden state с attention/MLP-добавкой | Квантование активаций; сложение пока FP32 | При фиксированной основной ветке ошибка добавки остаётся в сумме; residual не устраняет её автоматически |
| Gate/up и их произведение | Две ветки MLP после RMSNorm | Квантование весов проекций и/или активаций | При фиксированном gate: δm = g ⊙ δp; значения одной ветки масштабируют ошибки другой |
| Вход/выход down_proj | Промежуточный вектор MLP → hidden-размерность | Квантование весов и/или активаций | Ошибка промежуточного вектора преобразуется W_down и попадает в residual-добавку |
| Вход LM head и logits | Финальный RMSNorm → оценки элементов словаря | Квантование весов и/или активаций | Ошибки logits могут изменить вероятности и порядок кандидатов следующего токена |
| Веса любой Linear-проекции | Параметры слоя | Weight-only или weight+activation | При фиксированном X: E = X(W−W_hat)^T; weight MSE не определяет output MSE сама по себе |

## Что наблюдают текущие hooks

`../day4_hooks.py` собирает статистики входных активаций всех 211 `nn.Linear`-модулей для одного текста: min, max, mean, abs_max, std, p99, p99_9, kurtosis.

- std: деление на N, `correction=0`.
- p99/p99.9: квантили |x|, линейная интерполяция PyTorch.
- kurtosis: Pearson, без вычитания 3; для std=0 возвращается NaN.
- Q/K/V одного блока имеют общий вход, поэтому их входные статистики совпадают.
- Эти hooks не являются полным наблюдением всех тензоров: они не перехватывают отдельно embedding, RMSNorm, RoPE, softmax и residual-сложения.
- `linear_input_stats.csv` — снимок одного текста, а не агрегат calibration set.

## Границы выводов

Карта описывает возможные пути ошибок. Сравнение чувствительности тензоров, перенос на новые тексты, качество всей модели, скорость и реальная низкобитная упаковка пока не проверены.
